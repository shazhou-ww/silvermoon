# Implementation

## Steps

### I-S01: 建立声明模型与解释边界

定义 YAML schema、稳定节点与函数标识、类型化注册表及图校验器，并让运行时与展示投影消费同一模型。

### I-S02: 迁移命令流程与函数

逐步将 `what's next` 与 `check` 的副作用提取为业务层独立函数，将条件和终点答复提取为纯函数，并迁移到声明式解释器。

### I-S03: 生成流程浏览器与路径场景

从 YAML 和场景事实生成 HTML 流程浏览器，复用正式答复投影来预览每条终点路径。

## Acceptance criteria

### I-AC01: 命令行为保持兼容

现有测试与代表性路径矩阵证明迁移前后的完整命令报告、动作顺序和错误结果等价。

### I-AC02: 声明与实现可静态校验

自动检查证明节点可达、边有明确后备路径、函数标识均已注册，且非预期循环或悬空引用会失败。

### I-AC03: 单一来源可执行且可展示

测试证明运行时和 HTML 读取同一 YAML；HTML 能高亮场景路径并渲染对应终点答复。
