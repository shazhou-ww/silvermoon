# 声明化命令流程与可视化

## 问题

`what's next` 与 `check` 的流程、优先级、副作用和最终答复目前分散在命令式分支中，新增条件时难以同时确认所有路径、输出与文档仍然一致。

## 结果

以一份可验证的 YAML 流程定义作为两条命令的共同流程来源：运行时据此执行，HTML 据此完整呈现流程、选中路径及终点答复，使后续迭代成为对同一声明模型的局部修改。

## 边界

- YAML 只声明节点、边、优先级和稳定函数标识，不嵌入任意可执行脚本。
- 副作用由业务层中独立、可注入的函数实现；条件与终点结论保持纯函数，并由类型化注册表连接声明和实现。
- 保持现有命令报告、错误传播和生命周期语义；HTML 是同一流程定义的投影，不成为第二份流程来源。

## 验收标准

- `what's next` 与 `check` 的所有可达路径均由已校验的 YAML 定义驱动，并保持对外行为兼容。
- 可生成一个 HTML 浏览器，完整展示流程图，并能显示某个场景实际经过的路径与最终答复。
- 新增条件、副作用或终点答复时，声明、实现和路径覆盖之间的不一致会被自动校验或测试拒绝。
