# 缩短并分层 integration test 反馈

## 问题

当前 `pnpm test:integration` 在参考环境三次 test 阶段中位为 161.2 秒。调研显示，少数顺序大文件、V2 仓库 fixture 重建、压力规模与重复呈现断言共同形成关键路径，详见 [Integration test 调研](./IntegrationTestResearch.md)。

## 结果

以覆盖处置表为依据精简、迁移或合并用例，并把真实边界回归、完整风险验证、跨平台 smoke 和 live external 分层。高频快速层具有稳定时间预算，完整风险仍由 release 与 publish 门禁执行。

## 边界

- 保留事件流完整性、事务恢复、真实 Git 拓扑、跨进程 CLI 与发布链路等高价值行为覆盖。
- 删除、降级或迁移用例必须有覆盖依据，不以放宽产品正确性换取速度。
- 分层命令、CI 及开发文档保持一致；本 idea 不改变产品行为，CI 预算待真实 CI 样本确定。

## 验收标准

- 每个现有 integration 用例都有保留、合并、迁移或删除结论，并记录旧覆盖、新覆盖、运行层与理由。
- 同一参考环境连续三次运行快速层，其中位不超过 120 秒且任一次不超过 130 秒。
- release 与 publish 所需完整非 live 风险层及关键行为验证全部通过，分层边界和运行方式可从脚本与文档观察。
