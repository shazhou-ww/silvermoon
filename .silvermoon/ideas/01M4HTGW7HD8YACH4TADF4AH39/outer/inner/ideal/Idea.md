# 缩短并分层 integration test 反馈

## 问题

当前 `pnpm test:integration` 在本机基线为 159 项、测试阶段约 161 秒，完整命令约 169 秒。高成本真实 Git、CLI 与进程测试同低成本契约断言混跑，部分场景重复建仓或验证相同投影，压力规模与日常回归也未区分。

## 结果

以可复现基线和覆盖映射为依据，删除或合并冗余、脆弱及过度严格的用例，并按反馈速度与风险分层；频繁运行的 integration 层显著变快，完整高风险验证仍有明确入口和门禁。

## 边界

- 保留事件流完整性、事务恢复、真实 Git 拓扑、跨进程 CLI 与发布链路等高价值行为覆盖。
- 删除、降级或迁移用例必须有覆盖依据，不以放宽产品正确性换取速度。
- 分层命令、CI 及开发文档保持一致；本 idea 不改变产品行为。

## 验收标准

- 每个现有 integration 用例都有保留、合并、迁移或删除结论，并记录耗时与覆盖理由。
- 同一环境三次运行的中位数相较 161 秒基线至少下降 40%，且快速层可独立提供日常回归反馈。
- release 与 publish 所需完整层及关键行为验证全部通过，分层边界和运行方式可从脚本与文档观察。
