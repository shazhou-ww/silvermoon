# 统一 Silvermoon 运行时版本与 Schema 演进契约

## 问题

如果项目各自固化 Silvermoon 版本，运行时会逐渐碎片化，项目也难以及时获得修复与演进能力。项目真正需要长期依赖的是元数据 schema 契约，而不是某个 Silvermoon 二进制版本。

## 结果

所有项目统一使用环境中可用的 Silvermoon，并在不是最新版本时始终得到明确的升级提示。项目只声明其 schema 契约；Silvermoon 按契约校验元数据，并通过兼容规则与迁移能力承接 schema 演进。

## 边界

- 不再支持项目固定、解析或回退到项目专属的 Silvermoon 版本。
- 升级提示不等于静默升级；运行时与元数据迁移都必须保持可观察、可控制。
- 兼容承诺仅覆盖有效的已声明 schema，不猜测或静默修复损坏、未知的数据。

## 验收标准

- 项目接入契约不再要求 Silvermoon 版本依赖或固定版本，所有入口遵循统一运行时并持续提示升级到最新版本。
- 任一项目快照都能仅凭其声明的 schema 判定元数据是否有效，不需要对应时代的 Silvermoon 二进制。
- 每次 schema 演进都定义向前兼容规则，并为受支持的历史 schema 提供到当前 schema 的确定性迁移路径；迁移结果可校验且不静默丢失语义。
