# Implementation

本契约为准备阶段轻量初版，不属于 `acceptIdeal` 的验收范围；实施时再细化。

## Steps

### I-S01: 定义事件契约与兼容边界

定义仅上游可授权的 `setGateMode`，payload 为 `level: ideal | inner | outer` 与 `mode: explicit | waived`，各层独立且默认 `explicit`，非终态阶段可设置目标层。沿用现有显式决策约定：CLI 确认选项只是授权声明，不提供发送者身份认证，也不制造授权。规划 schema 兼容与既有事件读取；首期仅开放 inner 的 `waived`，明确拒绝未开放层的免验收请求，保留 ideal、outer 显式验收。实施时明确恢复 `explicit`、提交前后迟设策略及已通过阶段是否受影响的边界，不以通用形状暗授更大权限。

### I-S02: 贯通状态归约与用户指引

让事件归约持久恢复策略，保留既有真实验收事实，明确区分免验收通过；inner 仅在检查完成、同步和精确版本提交有效后进入 deploying，不生成或声称发生 `acceptInner`。统一 control、报告、guidance、canonical skill 与文档，维持陈旧版本失效规则和 outer 显式门禁，不依赖父子会话的临时状态。

### I-S03: 验证兼容性与策略边界

补充默认行为、旧事件兼容、上游权限、跨阶段设置、层间独立性和事件重放测试；覆盖免验收、恢复显式、迟设策略、陈旧提交、既有验收及未开放层拒绝路径，并运行相关测试与仓库校验。

## Acceptance criteria

### I-AC01: 默认行为与授权兼容

无策略的历史事件仍按全层显式验收运行；策略变更要求显式上游决策声明，合法目标层与当前非终态阶段独立，未开放层的免验收不生效。证明方法：schema、决策声明校验和旧事件回归测试，比较重放前后的层级策略与验收事实；不把这些测试描述成发送者身份认证。

### I-AC02: 有效提交免验收且事实可区分

inner `waived` 的精确提交满足检查与同步要求后进入 deploying，未写入 `acceptInner`；既有验收保留原意，outer 仍要求显式验收。证明方法：状态归约及报告集成测试，断言事件历史、通过依据、control 与下一步一致，并确认报告、guidance、skill 和文档不混淆两种通过方式。

### I-AC03: 逆转与迟设边界可复现

恢复显式、在提交前后迟设策略以及对已通过阶段的影响均有明确规则；陈旧提交不能因免验收而绕过精确版本校验。证明方法：将实施时确定的规则写入相关文档，以边界测试矩阵验证，并通过相关测试与仓库校验；未执行前不记录完成证据。
