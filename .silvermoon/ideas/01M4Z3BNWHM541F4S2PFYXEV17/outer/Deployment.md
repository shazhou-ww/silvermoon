# Deployment

本契约为准备阶段轻量初版，不属于 `acceptIdeal` 的验收范围；部署时再细化，不包含 npm 发布授权。

## Steps

### D-S01: 确认全局运行时与隔离样例

验证已安装的设备级全局 `silvermoon` 指向待验证 checkout，canonical skill 以链接注册；在隔离样例项目及其独立主线中开展验证，避免影响真实项目或借用父子会话状态。

### D-S02: 演示免验收到显式部署门禁

通过全局 CLI 在样例中对照默认模式与上游授权的 inner `waived`、outer `explicit`，完成真实检查、精确候选同步及提交，观察自动进入 deploying 后仍等待 outer 显式验收；只使用样例所需的明确授权，不代替真实项目验收。

### D-S03: 核验持久策略与边界报告

在新会话重新观察样例，对照已定义规则验证恢复显式、迟设策略和陈旧提交的可见结果，保留命令、运行时来源、版本引用、事件及报告证据；不在部署阶段修改源码或重复实施工作。

## Acceptance criteria

### D-AC01: 验证环境来源可追溯

所有样例操作使用已链接到待验证 checkout 的全局运行时与 canonical skill，样例不影响真实项目。证明方法：记录可执行文件解析、checkout 修订、skill 链接目标及隔离项目主线信息。

### D-AC02: 外部流程保持授权边界

默认样例仍等待显式验收；授权样例在精确提交有效后进入 deploying，历史没有伪造 `acceptInner`，outer 不自动完成。证明方法：对照真实 CLI 输出、同步后的候选引用及事件历史，展示通过依据与等待门禁。

### D-AC03: 跨会话与边界行为一致

新会话可恢复策略和通过依据，恢复显式、迟设策略与陈旧提交的实际报告符合已定义规则。证明方法：保留新会话的观察输出及样例边界操作前后对照；证据仅在执行后记录，不将父子会话交接视为验收事实。
