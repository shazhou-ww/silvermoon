# CLI 职责边界与模块化重构

## 意图

在保持既有 CLI 行为、仓库协议和调用方兼容性的前提下，重新划分 Silvermoon
CLI 及其共享核心的职责，使规则判断、用例编排、仓库读写和输出展示高内聚、
低耦合，每个模块具有明确且尽可能单一的变化原因。

这是一轮结构性重构，不是功能重写。衡量结果的是职责隔离、独立验证能力和
行为等价，而不是目录数量、文件数量或人为的文件行数上限。

## 背景

当前 CLI 包含查询 idea、导航下一步、创建 idea、检查快照和事件操作。
已有纯状态归约、四投影报告、Git 快照读取、可恢复状态事务、分段事件流和
增量读取等能力，应当保留并复用。

需要改善的边界包括：公共导出入口同时实现检查用例；导航模块承载可被创建
流程复用的仓库准备检查与操作指令；命令运行时与纯 reducer、trace 接入混合；
结构化响应与 Markdown 渲染混合；事件请求、历史证据、决策校验、事务执行和
恢复路径集中在同一命令实现中。项目接入、配置、idea 布局和 Git 能力也需要
明确读取、解析、策略与编排各自的归属。

本契约以已集成到 primary 的当前能力为兼容基线，包括分段事件存储、游标查询、
经过验证的增量读写，以及允许在正确跟踪 primary 的任意本地分支创建 idea。
不得把较早版本的单文件事件存储或本地主分支名称限制重新引入。

## 期望结果

1. CLI 入口只负责参数与输入适配、调用用例、选择输出及映射退出码；公共包入口
   只承担受控导出与必要组装，不承载某个业务用例的实现。
2. 每个用例清楚表达一个用户意图及其执行顺序。命令之间不依赖另一命令的实现；
   共享能力有独立归属，而不是收进无所不包的服务或上下文对象。
3. 生命周期、事件变化、查询及 readiness 的规则可通过纯输入输出验证。
   纯规则不直接访问文件系统、子进程、网络、终端、时钟、随机源或 trace 存储。
4. 仓库事实读取、策略判断和副作用执行相互分离。快照目标及其 commit、tree、
   内容来源明确，不混用工作区、暂存区和已提交版本，也不在普通读取中隐藏 fetch。
5. 单次命令的消息顺序、action 配对和报告完成过程具有独立运行时边界。
   结构化 response 仍只由 intention 和最终内部 observation 生成；
   Markdown、JSON 和 TUI 不重新推导业务状态或执行仓库操作。
6. idea 持久事件与单次命令消息流保持不同职责；创建脚手架与状态事务保持
   各自的并发、失败清理和恢复语义，不因抽象复用而削弱保护。
7. 项目接入、语言解析、配置与 skill 检查、idea 读取、Git、事件存储及展示
   各自有可说明、可验证的边界。纯解析函数可以保留在所属适配器中，不因其
   纯粹而强行归入业务领域。
8. 修改展示、调整业务策略或替换底层读写实现时，不必同时改动无关职责。
   模块依赖可自动检查，用例可使用受控依赖验证执行顺序，纯规则测试不需要真实 Git。
9. 重构可以分批验证与集成，每批保留可用 CLI，不以一次性大搬迁掩盖行为变化，
   也不把已有批量读取或增量路径退化为反复扫描完整历史。

## 范围

### 范围内

| 职责边界 | 应承担的能力 |
| --- | --- |
| CLI 适配 | 参数、输入文件、调用包装、输出选择、错误与退出码映射 |
| 应用用例 | 查询、导航、创建、检查，以及事件读取、写入、修订与恢复的编排 |
| 观察与共享检查 | 项目、配置、idea、guidance、历史证据及明确快照的观察组装 |
| 命令运行时 | intention、observation、action、response 的有序生命周期 |
| 响应组织 | 纯响应投影、诊断与本地化下一步指令 |
| 领域与协议规则 | 生命周期、持久事件、查询、准备条件、命令消息 reducer 与不变量 |
| 基础设施 | Git、快照、项目资源读取、脚手架写入、事件存储、派生缓存、事务和 trace |
| 展示 | JSON、Markdown、表格、日期格式化与 TUI |
| 组装与兼容表面 | 默认依赖组装、既有公共导出、包内资源定位及调用方契约 |

为上述边界所必需的测试、维护文档及包安装验证在范围内。
Agent 集成作为既有 CLI 和包子路径的调用方纳入兼容性验证，但不因此扩展其功能。

本契约不预先锁定目录名、类结构、接口文件数量或具体拆分顺序；
实施阶段再将职责要求收敛为可验证的设计和分批方案。

### 范围外

- 新增命令、产品能力、参数语义、生命周期状态或交互方式。
- 改造 Agent 会话管理、权限模型、跨项目调度或常驻进程能力。
- 重写事件协议、合并两类事件模型、替换持久状态权威或发起仓库格式迁移。
- 改变人工批准、验收、放弃及恢复授权规则。
- 引入通用插件框架、依赖注入容器、命令总线或全仓语言迁移。
- 顺便修复无关问题、改写并发历史、发布 npm 包或改造发布流程。

## 约束

### 命令行为保持独立

| 命令或路径 | 必须保留的行为 |
| --- | --- |
| `list-ideas` | 查询本地有效清单，不要求工作区干净、upstream 就绪或远端可用，不 fetch |
| `whats-next` | 先处理本地准备问题，再允许 fetch、提交关系判断和 idea 路由 |
| `create-idea` | 要求干净的本地分支及正确 primary upstream；本地分支名称不限，不 fetch 或要求远端对齐 |
| 本地 `check` 目标 | 只验证所选快照及适用的事件历史边界，不套用任务推进的 readiness，不 fetch |
| `check --remote` | 使用已提交的 primary 坐标获取并验证远端目标，不修改调用方分支、暂存区或工作区 |
| 完整事件 replay | 保留完整归约与诊断语义，不将其替换成局部查询 |
| 游标事件查询 | 绑定已处理的精确前缀，只返回后续事件；不冒充完整归约，不自动重置失效游标 |
| 本地 `ping/pong` | 保留不依赖 primary fetch 的本地精确流前提和离线写入路径 |
| 状态事件写入与恢复 | 保留精确日志、primary、世界版本、人工决策及并发校验，不自动重放过时请求 |

### 对外协议与存储

- 保持五个公开命令及其现有参数、默认值、错误分类、退出码、stdout/stderr
  和公共导出语义；不同命令的受阻结果不能被统一映射为同一种退出状态。
- JSON 仍恰好包含 `intention`、`observation`、`actions`、`response` 四个投影。
  保持 schema、trace 版本、action 配对、guidance 内容与 provenance 的边界。
- 保持 `create-idea --language` 的持久内容语言语义，以及其他相关命令的临时
  输出语言语义；保持 human、agent、JSON、双 TTY 判定及 TUI 懒加载行为。
- 保持 v1 状态兼容和当前 v2 分段事件协议，包括连续序列、1000 条分段边界、
  单条记录字节限制、规范字节、事件目录 Git tree digest 及 SHA-1/SHA-256 支持。
- 保持 checkpoint、cursor 和认证派生缓存不是事实权威的边界；格式错误、
  不可信缓存、未知内容或读取失败不能变成成功结果、默认授权或修复许可。
- 保持完整校验、历史边界、迁移兼容、显式恢复、精确重试和未知内容保护。
  创建失败只能清理本次操作仍拥有的内容；状态事务不能退化为无保护的普通写文件。
- Agent 调用方继续使用项目自己的 CLI 与协议解释，不复制其生命周期规则；
  保持独立包子路径、声明及安装态行为。

### 工程与验证

- 依赖方向清晰且无新增环：领域规则不反向依赖应用、CLI、展示或真实 I/O；
  应用用例不依赖具体命令适配器，也不通过公共导出入口绕行内部实现。
- 用现有测试体系验证行为等价，并补充职责边界与受控依赖测试。
  不以减少断言、放宽错误、跳过并发场景或关闭 sanity I/O 隔离换取通过。
- 保留现有标题读取、Git 批量读取、分段摘要、游标后缀读取和认证增量追加的
  可测预算；同时保留冷路径、变更路径、完整 replay 与跨平台校验的必要工作。
- 迭代使用 `pnpm check:sanity` 和变更相关测试；提交前使用 `pnpm check:commit`；
  CLI 实现交付前使用完整 `pnpm check`。工作区代码测试与暂存元数据检查不得混淆。
- 保持源码仓库使用本地入口，不依赖自身发布包。保护现有 idea、用户修改和并发
  历史，通过普通非强制 Git 同步；新增契约和 ledger 勾选均不代表人工决策。
