# 专业导向模型

## 价值导向

这里的价值不是一般意义的好坏，而是专业方法规定的推进方向：将相关的高维世界状态投影到具有唯一最高层级的有限全序集。最高层级唯一，但满足它的具体世界状态可以有多个。

层级是序数，不表示等距收益。导向不存在严格上升的闭环，但执行过程可以反复尝试、保持原层或下降；结果由新的现实观察确认。

不同 Idea 或专业角色可以定义不同导向。本次只验证 Silvermoon，不设计多角色协调协议。

## 最小公共契约

以下是讨论确定的概念接口；具体命名和与现有报告的适配在实施时细化。

```ts
type Target = Readonly<Record<string, unknown>>;

type Problem = {
  code: string;
  description: string;
};

type Observation = {
  level: number;
  problems: readonly Problem[];
};

type LevelDefinition = {
  level: number;
  description: string;
};

type ProfessionalModel = {
  observe: (target: Target) => Promise<Observation>;
  guide: (code: string) => string;
  describe: () => readonly LevelDefinition[];
};
```

- `Target` 是固定类型的 key-value 对象，不再暴露泛型，便于声明式描述观察对象，例如项目与 Idea；它不是完整世界状态或内部观察上下文。能力定义需声明所需字段并在运行时验证，缺失或类型错误必须明确诊断，不能默认为有效；目标参数无效与业务层级未达成应区分。
- 层级为非负整数，0 是兜底层；证据不足时也返回层级，并显式报告无法进一步判断的问题。
- `code` 连接问题类别与指导，`description` 说明本次问题的具体事实。
- `guide` 是全函数；未知 code 返回明确的兜底指导，不伪装成已知问题的解法。返回字符串作为 skill 内容还是引用，在实施时明确统一约定。
- `describe` 解释有序层级及其唯一最高层；无问题不替代最高层判定。

## 原子检查与拼装

专业能力由声明式 YAML 定义与统一类型的检查副作用组成。YAML 描述层级、检查顺序、问题与 skill 的映射；检查名称引用实现，不在配置中嵌入可执行脚本。

每个检查接受相同类型的 Target，返回 Promise，结果为通过或未通过及非空问题列表。二维数组的第 0 项表示 0 到 1 的检查，第 1 项表示 1 到 2 的检查，以此类推。

层内检查也是子阶段：顺序逐关执行，首个未通过处停止，不继续收集后续关卡的问题。当前层的全部检查通过才升级；空检查组自然通过。大层级是对细粒度关卡的压缩，检查顺序属于专业方法论。

每次观察从起点重新判定；共享状态和缓存仅在本次 observation 内有效，可通过闭包或类似 state hook 的机制管理，不暴露在公共参数中，也不要求引入 React。观察是一段采样过程，不保证瞬时或一致性快照；版本相关判据仍需明确证据有效性。

预期的不可用、未满足或信息不足应报告为问题；程序缺陷不能被统一吞成正常阻塞。配置中的未知检查、无效层级或失效引用必须显式诊断。

## 责任边界与验证

人和工具定义方向、判据与指导，Agent 根据问题及 skill 选择具体解法。运行器不自动执行 skill；人工决定、权限与外部等待可以阻塞推进，但不能被自动替代。

Silvermoon 的现有报告仍是对外契约。适配不能为符合抽象而删除已有事实、改变非阻塞 advisory、语言规则或精确 revision 的控制权与接受语义。

本次证据应区分两件事：抽象可以承载 Silvermoon；抽象适用于其他领域。只承诺验证前者。
