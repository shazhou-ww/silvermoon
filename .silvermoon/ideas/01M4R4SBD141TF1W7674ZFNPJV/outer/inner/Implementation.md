# Implementation

## Steps

### I-S01: 建立专业能力 module

依据[导向模型](./ideal/professional-model.md)定义能力、配置及原子检查的统一契约，提供拼装执行函数与观察内状态机制，不建立独立发布包。

### I-S02: 适配 what's next

将现有导航实际接入能力定义与执行机制，保留领域报告、阻塞优先级、控制权、语言和版本语义。

### I-S03: 验证并记录抽象边界

补充抽象及适配测试，更新直接相关文档，明确哪些行为通用、哪些保留在 Silvermoon 内。

## Acceptance criteria

### I-AC01: 拼装语义可验证

测试覆盖逐关停止、全部通过、0 级兜底、问题说明、未知 code 指导及观察内共享与跨观察隔离；配置错误和程序错误不被伪装成成功。

### I-AC02: 导航行为兼容

针对整备、选取 Idea、生命周期与人工或外部等待的测试证明实际经过新抽象，保持现有报告形状、优先级、语言、非阻塞 advisory 和精确版本控制。

### I-AC03: 仓库验证通过

通过 `pnpm check:sanity`、变更专项测试和 `pnpm check`，记录精确命令与结果；文档明确单场景验证不证明跨行业普适性。
