# pnpm check 性能基线

## 环境与方法

- OS：Windows。
- Node.js：24.11.1。
- pnpm：11.22.0。
- 基线 commit：`c5639dbb9d06c2613b707e8d615cb4a8a6fe8636`。
- 先运行一次 `pnpm check` 预热，再连续运行五次相同命令；五次均退出码为 0。
- 预热运行包含首次依赖安装，耗时 220,468 ms，不纳入五次基线样本。
- 五次完整检查的原始墙钟样本（ms）：185,357、174,495、160,047、176,941、187,818。
- 中位数：176,941 ms；范围：160,047–187,818 ms。

## 分层测试样本

`pnpm check` 同时启动六个独立门禁。其测试 runner 输出了以下可分层比较的
`duration_ms`；较短门禁的独立耗时尚未由当前调度器报告，I-S03 将补齐这些观测。

| 命令 | 五次样本（ms） | 中位数（ms） | 测试数量 |
| --- | --- | --- | --- |
| `check:quick` — unit | 15,561; 13,115; 11,887; 11,617; 16,314 | 13,115 | 78 |
| `check:quick` — contract | 13,666; 13,262; 9,894; 10,341; 13,705 | 13,262 | 31 |
| `test:integration` | 182,816; 172,344; 157,400; 174,771; 184,992 | 174,771 | 116（114 通过，2 个 Windows symlink 权限跳过） |
| `test:e2e` | 117,963; 138,449; 101,566; 115,014; 123,178 | 117,963 | 1 个 installed-package smoke |

Integration 中位数几乎决定完整检查墙钟，是本阶段的主要可优化门禁。E2E 样本有
明显波动，含 npm 安装和外部 skill 安装；不得将网络或缓存波动归因于代码优化。

## Fixture 探查

在同一环境中，对 `createRepository()` 默认隔离仓库执行一次预热和五次测量；每个
仓库在计时后立即按其返回的精确临时路径清理。原始样本（ms）：1,507、1,495、
1,464、1,495、1,621；中位数 1,495 ms。默认 helper 每次都创建本地仓库及 bare
primary、配置 remote 并 push；I-S02 将检查仅需本地仓库的调用是否能省去这项未用
准备，同时保留确实验证远端行为的 fixture。

## 优化后测量

在 Windows、Node.js 24.11.1、pnpm 11.22.0 和最终候选 commit
`ac2bcaaf33c227bc79443553655290ff70d10554` 上，运行一次预热后连续执行五次
`pnpm check`。预热包含首次依赖安装以外的完整门禁，结果及五次样本如下；所有
计量运行均以退出码 0 完成。

| 门禁 | 预热（ms） | 五次样本（ms） | 中位数（ms） |
| --- | ---: | --- | ---: |
| 完整检查 | 144,038 | 145,749; 180,889; 199,106; 128,053; 125,910 | 145,749 |
| `test:integration` | 120,046 | 110,622; 169,374; 161,765; 109,908; 104,513 | 110,622 |
| `check:quick` | 45,011 | 42,417; 83,468; 41,677; 48,268; 39,096 | 42,417 |
| `test:e2e` | 143,962 | 145,639; 180,767; 199,022; 127,982; 125,851 | 145,639 |

完整检查中位数由基线 176,941 ms 降至 145,749 ms，降低 17.63%，达到至少降低
15% 的验收标准。五次全量样本波动明显，故保留所有数据，不以单次最快值或缓存、
网络、排队变化替代中位数比较。最终 integration 为 119 项（117 通过，2 项因
Windows 符号链接权限按原有原因跳过），`check:quick` 包含 91 个 unit 与 32 个
contract 测试，installed-package E2E 为 1 项。

## 历史对照与限制

已验收 `faster-test-suite` ledger 记录的基线为 Node.js 24.12.0、pnpm 11.22.0：
`pnpm check` 中位数 54,585 ms、`test:integration` 中位数 32,337 ms、
`test:e2e` 中位数 14,527 ms，integration 为 75 个测试。当前环境的 Node.js 补丁
版本不同，integration 为 116 个测试，E2E smoke 也可能已扩展，因此该历史数据只
用于定位变化，不作为同条件前后验收基线。
