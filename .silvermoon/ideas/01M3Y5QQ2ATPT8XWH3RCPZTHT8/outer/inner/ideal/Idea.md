# V2 分段事件流与完整流 HEAD

## 意图

将所有 V2 项目的 idea 事件持久化从单个 `events.jsonl` 改为一条逻辑流一个 folder，
以固定事件条数确定性分段，同时提供覆盖完整有序事件内容、可验证增量聚合的流 HEAD。
物理切段不能改变事件顺序、事实、幂等或逻辑 session 的连续性。

## 背景

目前一个 idea 的业务与交互事件共用单个 JSONL 文件。历史不断增长时，单文件读写、
历史比较与提交前态校验需要演进为一致的分段存储契约，而不是增加日期切片或新 session。

本 idea 是 `daemon-event-bridge`（`01M3SJ90WVJB56Z1PP72BPAHFZ`）的前置修订：
后续 bridge 设计需要建立在本契约收敛并完成后的存储基础上。本次只在新契约中记录依赖，
不修改该 idea 的讨论稿、契约或状态，也不把本次创建当作该依赖已完成。
未来治理流可复用同一存储基础，但治理流及 daemon 生命周期不在本 idea 实施范围。

现有 `src/state-transaction.js` 的 `digest` 是对原始字节计算 SHA-256。
`src/event-command.js` 的 `appendLocalInteraction` 已使用 `expectedLength` 与
`expectedDigest` 绑定前态，并核对该前缀之后的准确事件记录来识别 `already-present`。
不能把正确的已有幂等能力误判为仅凭 sequence 判断重试；sequence 本身未必需要改变。

## 期望结果

### O-01: 每条流一个 folder，固定条数切段

所有 V2 项目 idea 流使用一致的 folder layout。给定相同事件序列和已收敛的分段参数，
分段边界应确定且不受时区、日期、重启或机器影响。按固定事件条数填充 segment；
满段封存且不再改写，尾段负责追加。空流与刚好满段时的表示必须有唯一规范。
取消日期切片；跨日、重启或物理切文件均不是切换逻辑流或逻辑 session。
sequence 在整个逻辑流中连续，不在 segment 边界归零。

证明要求：空流、边界前后、连续多段和跨日场景得到相同的有序事件与状态；
正常追加不重写封存段。最大条数尚未确定，1024 仅是候选，不是批准值。

### O-02: HEAD 绑定完整有序内容

流 HEAD 必须覆盖从流起点到当前尾部的完整有序内容，不能仅使用最后一个 sequence、
尾段摘要、文件数量或 OS 目录元数据。规范 folder digest 要明确纳入哪些规范内容，
排除锁、temp、checkpoint、权限与 mtime；相同规范内容在不同环境产生相同 HEAD。
路径、段次序、内容边界与空流需要确定性、无歧义编码，并约束无关条目或异常 layout。

采用可验证的增量聚合，正常追加和重复读取不应每次读取全部历史。
聚合不能只信任未经验证的缓存；必须定义来源绑定、验证路径、失效与重建规则。
HEAD 与既有 world Git tree revision 是不同概念，不得悄悄替换生命周期批准的 revision。

证明要求：改变、删除、交换或插入任一历史段或事件均能被发现；相同尾段和 sequence、
不同历史内容不能通过同一前态校验。改变排除项不改变规范 HEAD。
测试需验证实际读取范围与增长成本，不能仅凭接口名称声称增量。

### O-03: 前态校验、准确幂等与 stale 拒绝

相同 HEAD 只证明同一前态，不证明同一次提交。重试必须能证明原请求已经在原前态之后
写入准确对应的记录；不能仅因前态或 sequence 相同就返回 `already-present`，
也不能仅因当前 HEAD 已变化就重复写入已完成的原请求。

保留正确幂等语义以及可区分的观察、候选已写入、已存在、无状态变化和冲突结果。
两个不同请求竞争同一前态时，不能覆盖、自动重编号或把一方的成功冒充另一方的成功。
stale 必须显式拒绝并交还发送方重新观察、判断意图；接收方不得自动刷新 HEAD
并重试旧意图。实际 protocol、请求 identity 与 receipt 字段仍待收敛，
不预先要求改变事件 sequence 或扩展事件 payload。

证明要求：同一请求重试、不同请求同一前态、成功后丢失回执、尾段与跨段并发，
以及请求之后又有其他追加时，均保持准确事实和幂等判断；非法或损坏历史不能伪报成功。

### O-04: V2 内部迁移保全事实

schema 与 layout 演进后仍为 V2，不引入 V3。V2 尚未发布，目前只有 Silvermoon
本仓库使用；旧 V2 到分段 V2 只提供仓库内部一次性迁移脚本，不新增对外 CLI
迁移命令，不为外部支持仓设计旧 V2 兼容或迁移承诺。

脚本必须校验准确来源、历史边界和候选，完整保留事件顺序、payload、sequence、
身份、既有决策及其有效性语义，不捏造事件、不丢失未知或并发工作。
计划、应用与中断恢复应可观察、可验证、可恢复；来源、primary 或候选发生变化时
显式阻挡，不能分叉后宣称迁移成功。已完成迁移的重复调用不得再次追加或重复迁移。
保持无关 world 内容与 ledger 不变；明确如何验证迁移前后逻辑流与状态等价。

保留既有面向已发布版本的迁移能力，特别是独立的 V1 到 V2 迁移及相关恢复支持；
不要因删除未发布旧 V2 支持而误删无关能力。必要的适配不得变成新迁移授权。

### O-05: 全相关表面一致

schema/layout、读取与回放、写入与历史验证、创建脚手架、primary Git 比较、
runtime 追加边界、公开与内部类型、测试、文档、skill 和内部迁移使用同一逻辑流契约。
查询、追加、历史比较与恢复不能各自定义不同 HEAD 或段顺序。
V1 及已发布版本的既有行为不因本次分段演进无故改变。

证明要求：真实文件系统与 Git snapshot 中的读取、追加、历史边界、创建、
并发与恢复测试覆盖跨段情况；类型、包内容、CLI、文档与注册 skill 一致，
内部迁移工具不意外进入面向外部的包能力。

## 范围

### 范围内

- 收敛以上存储、HEAD、幂等、历史验证和恢复契约，再在获得明确 ideal 批准后实施。
- 统一所有 V2 idea 流的 schema/layout 与相关读写、脚手架、primary 比较和 runtime 边界。
- 可验证增量聚合、checkpoint/cursor 的派生性与校验要求，以及准确的性能证明。
- 本仓库旧 V2 到分段 V2 的内部一次性迁移及其来源校验、等价证明与恢复。
- 相关类型、测试、文档、canonical skill 与注册副本的一致更新。

### 范围外

- daemon loop、调度、发送策略、自动 stale 重试、自动批准或其他 bridge 运行时功能。
- 治理事件及治理生命周期实现；只保留未来复用存储基础的边界。
- V3、对外旧 V2 迁移 CLI、外部支持仓兼容/迁移承诺和 npm 发布。
- 改写原 `daemon-event-bridge` 讨论稿或将其未提交内容带入本候选。
- 本次创建阶段的事件流运行时实现、内部迁移执行与生命周期批准。

## 约束

- 本次授权仅完善 Ideal World；Implementation、Deployment 和 ledger 保持同步占位且未勾选。
  创建及普通同步不等于 `acceptIdeal`，不得记录未经授权的决策。
- 事件仍为唯一事实来源；checkpoint/cursor/聚合缓存不能成为新的业务事实或审批来源。
- 正常追加保持不可变历史保护与既有授权修复边界；分段不是重排、删改或重放旧决策的许可。
- 事务必须保护准确前态与操作所有权；并发与崩溃中不能丢工作、重复事件或返回假成功。
  进程中断恢复与硬件掉电持久性需分别说明保证，不能混为一谈。
- 仅对新候选进行合法验证、提交和普通非强制同步；发布 primary 前重观并发变化，
  不 reset、force-push、stash 或操作其他工作区来隐藏冲突。

## 待解决问题

以下事项必须在批准前明确收敛，不能把候选值当成已批准设计：

- 每段事件上限及依据：1024 为候选；如何证明边界、读取成本与实际工作负载适配。
- folder 与 segment 命名、排序、连续性、空流、刚满段尾部和异常条目的规范表示。
- 哈希算法、域隔离与无歧义编码、规范内容覆盖、聚合结构及完整验证与增量验证的关系；
  不能直接假定单文件原始字节 SHA-256 等同于 folder HEAD。
- 单事件大小上限及超限诊断；固定条数分段是否还需要独立的资源界限。
- 原子追加、封存与切段的提交点、锁粒度、事务所有权、可见性与平台持久性保证。
- checkpoint/cursor 的形式、精确来源绑定、失效与重建、历史读取和 Git snapshot 的处理；
  checkpoint 必须排除在规范 digest 之外。
- 并发写入、未知外部编辑、崩溃阶段和恢复/回滚规则；正常历史保护与授权修复如何跨段保持。
- HEAD precondition 与请求 identity 的具体 protocol、准确重试识别和 receipt 类型；
  如何保留现有前缀加准确记录的正确幂等语义，而不自动刷新前态重试。
- 内部迁移来源识别、历史 format boundary、可观察计划与等价验证、
  原子应用/恢复和与既有 V1 迁移能力的适配边界。
