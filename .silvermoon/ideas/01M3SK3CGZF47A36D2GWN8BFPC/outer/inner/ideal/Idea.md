# 隔离的项目运行时协议与 Copilot CLI 适配

## 意图

让调用方通过明确的进程间协议使用项目对应版本的 Silvermoon，而不与其
包版本或 schema 绑定。提供统一 Agent 适配边界和首个 GitHub Copilot CLI
适配器，无需设备级 daemon 即可完成受控执行及多轮 session 交互。

## 背景

本 idea 从
[设备级 daemon 总体设计](../../../../01M3SJ90WVJB56Z1PP72BPAHFZ/outer/inner/ideal/Idea.md)
拆出，将跨版本协议和真实 Agent 能力验证前置，避免直到 daemon 集成时才
发现无法恢复 session 或向执行中的会话送达新指令。

最终对接以
[事件化状态](../../../../01M3SJTKFRQ19DP0RPPJACKGMC/outer/inner/ideal/Idea.md)
和
[本地交互协议](../../../../01M3SJXTDXW54FFCSKSBJMMRBZ/outer/inner/ideal/Idea.md)
为基础。协议设计和 Copilot 能力验证在本项获准后可以与前两项并行探索，
但最终验收必须使用它们的真实项目行为，不能只有 mock 适配器。

## 期望结果

### 项目语义与调用方版本解耦

项目对应版本 Silvermoon 在独立进程中读取和解释项目事件、schema 及世界
revision，给出下一步、继续执行或交还上游的结构化结果。
调用方不能用自身携带的模型重新解释该项目，也不能要求所有项目同步升级。

不同 Silvermoon 包版本及项目 schema 可以通过明确的调度协议协作；
所需兼容性限定在进程间协议，而不是强制包版本彼此兼容。
运行时发现、协议能力和不支持的情况必须明确，不能静默切换到另一版本。

正常流程判断归项目版本。调用方负责执行结构化结果，并将结果或运行故障
交回项目运行时；这不建立第二套生命周期状态机。
无状态 CLI 与 `whats-next` 保持独立可用，共用项目语义。

### 可实际使用的 Copilot 适配

Silvermoon 提供统一适配边界，并内置 GitHub Copilot CLI 的启动、会话恢复
和消息收发能力，而不是只交付协议、把所有连接工作留给外部宿主。
具体使用的 CLI 或程序化能力必须经实际验证，不根据产品名称推断支持情况。

每个 session 明确关联项目、工作区和 idea，避免把消息或执行结果投递到
错误上下文。同一 idea 的多轮交互尽量复用同一 session；失效时才新建，
并明确恢复依据，不把新 session 冒充原有会话。

### 运行中追加指令与求助

适配器落实交互协议的“随时可追加 ping”，在下游运行中仍允许接收后续指令，
不要求上游先取得轮次或等待确认停止。新增指令进入当前关联的 session，
不另启同一 idea 的并行执行者。

接收、送达、处理和结果确认分别可观察。Copilot 不支持立即消费运行中指令时，
适配行为必须明确实际处理边界，不能丢弃指令、无限搁置或将排队冒充生效；
发现无法满足契约时应显式提出阻塞，而不是把产品规则改回严格乒乓。

下游完成当前工作后把结果交回 Silvermoon，由项目版本观察并决定后续；
不把整个 `whats-next` 循环策略重新交给下游 Agent。
下游无法自行推进时可表达求助，包括 sign-off 和 Git 提交失败。
上游追加的“暂缓提交，先调查 Git”能实际送达并得到执行或明确阻塞结果。

### 恢复不等于重放副作用

适配器能报告会话和执行状态，明确处理连接丢失、进程退出及结果不确定。
恢复时优先确认已有执行，而不是仅因缺少完成事件就重复派发。
无法确认是否仍在执行或是否已产生副作用时，必须显式报告不确定性。

本项提供单 session 及单次执行的恢复能力，供后续 daemon 使用；
不承担全设备调度状态或 daemon 重启后的全局恢复。

完整执行日志归下游 Agent。Silvermoon 不采集、存储或管理完整对话、工具
调用和逐步输出；必要状态、结果和证据引用按前置事件协议记录。

### 无需常驻 daemon 的验收边界

通过受控调用方与真实 Copilot CLI，证明启动、执行、回传、复用同一 session、
运行中追加指令的实际送达边界，以及失效后的恢复或明确阻塞。
证明不同项目版本由各自进程解释，而非被调用方的 schema 覆盖。

可控故障场景证明旧结果不会吞掉新指令，连接丢失不会导致盲目重执行，
Git 阻塞后的诊断指令仍可执行。该验证不需要先建设跨项目常驻调度器。

## 范围

### 范围内

- 项目运行时发现、进程隔离、调度协议和不支持能力的显式报告。
- 项目流程判断与调用方执行的职责分界及结构化结果。
- 统一 Agent 适配边界和首个 GitHub Copilot CLI 适配器。
- session 关联、复用、重建与状态报告，以及运行中指令的真实送达。
- 单次执行恢复、求助和 Git 诊断指令的端到端证明。
- 相应文档、skill 指引和无需 daemon 的受控验收场景。

### 范围外

- 重建前置项的事件存储、迁移、交互 reducer 或写入子命令。
- 设备级常驻 daemon、全设备资源调度与跨项目持续循环。
- 其他 Agent 产品的全部适配、完整执行日志和聊天 UI。
- 跨设备锁、自动批准或验收、强制全部项目使用同一 Silvermoon 版本。
- 对 Copilot 无法提供的能力静默降级，或仅用 mock 宣称真实适配已完成。

## 约束

- 同一 Silvermoon 包提供这些能力，不引入必须单独安装的 daemon 产品。
- 统一 Agent 接口和首个 Copilot 适配器放在本仓库的独立模块目录；
  不为首个实现另建仓库或发布独立包。后续其他适配器遵守同一接口。
- 本项可以先验证高风险的外部 Agent 能力，最终集成验收依赖
  `event-state-model` 和 `local-agent-handoff`，不反向依赖 daemon。
- 交互事件仍由项目版本 Silvermoon 子命令校验并追加，不要求 Agent
  直接编辑 JSONL，也不让调用方改写项目事实。
- 保留工作区未知修改与并发历史；session 失效不是清理工作区的授权。
- 真实 Agent 运行、认证和权限不足必须显式报告，不能伪造执行或恢复证据。
- 与其他前置项共同支撑 `0.4.0`；本项完成不独立触发 npm 发布。
- 本次只记录契约，不启动真实执行、不改 schema，也不记录人类批准或验收。

## 实施时需细化

进程间消息格式、协议协商、项目运行时发现方式、Copilot 接入方式、会话身份、
消息送达边界与不确定执行的恢复策略，由实施契约结合真实能力验证确定。
这些细节不改变项目语义自治、session 复用和运行中允许追加指令的目标。

[Agent 适配接口设计契约](./Agent-adapter.ts) 描述单实例、多 session 的类型
边界及全双工反馈语义。它是 Ideal World 的配套设计，不是运行时代码；
实现时需结合真实 Copilot 能力验证，并在实施契约中确定具体源码路径、
公开导出方式，以及本仓库现有 JavaScript 运行时代码如何承载该 TypeScript
类型契约。本次讨论不构成对 ideal revision 的正式批准。
