# Implementation

## Steps

### I-S01: 建立可重复的耗时基线

在固定 Node.js/pnpm 版本和空闲机器条件下，对 `pnpm test`、`pnpm test:integration`、`pnpm test:e2e` 与 `pnpm check` 分别完成一次预热和至少五次计时，记录中位数、离散情况及测试数量。进一步按测试文件和高频 fixture 操作分析耗时，确认主要瓶颈后再选择优化手段。

### I-S02: 并行执行独立发布门禁

保留 unit、contract、integration、e2e、包内容、Markdown 和 skill 检查的现有命令与覆盖范围，通过跨平台调度器并行执行不存在共享可变状态的发布门禁。调度器使用当前包管理器入口启动子任务，等待所有任务结束，并保持每项检查可单独运行。

### I-S03: 保持失败可诊断性与隔离

为进程启动失败、非零退出和多个并发失败提供明确汇总，不因首个失败提前返回或产生成功形状的空运行。通过单任务、串行调度和并行调度验证各检查不依赖顺序，且不修改工作区 Git 状态或泄漏临时资源。

### I-S04: 固化快速反馈与回归测量

保持现有命令兼容，完善本地开发说明和必要的计时辅助，使贡献者可选择快速 unit/contract 反馈或完整发布级检查。性能证据应输出各层耗时和总耗时，但避免依赖易波动的绝对硬超时。

## Acceptance criteria

### I-AC01: 完整检查中位耗时至少降低 30%

在与 I-S01 相同的机器、工具版本和测量方法下，对优化前后各至少五次预热后 `pnpm check` 运行取中位数；优化后中位数必须较基线降低至少 30%，并在 ledger 中记录原始命令、环境摘要、各次结果和计算值。

### I-AC02: 所有正确性门禁保持通过

运行 `pnpm test`、`pnpm test:integration`、`pnpm test:e2e` 和 `pnpm check`，全部以退出码 0 完成；同时比较优化前后发现的测试数量及 `pnpm check` 所含检查，证明没有通过跳过套件、删减断言或缩小包与 skill 检查范围换取速度。

### I-AC03: 测试保持隔离且无顺序依赖

分别运行调度器单元测试和受其编排的分层命令，再以串行、正常并行和反向任务顺序重复调度器测试；所有运行均通过，完成后不存在遗留临时仓库或对工作区 Git 配置、引用和环境变量的修改。

### I-AC04: 分层反馈路径清晰可用

按照更新后的贡献说明从干净 checkout 执行快速测试入口和完整 `pnpm check`；命令、适用场景和性能测量方法均可直接复现，Markdown 链接检查与 `git diff --check` 通过。
